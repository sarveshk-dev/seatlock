# SeatLock (Oracle edition): Concurrent Seat Booking Engine

React + Node/Express + **Oracle Database**, with live seat updates over WebSockets.
Many users can try to book the same seat at the same moment, and exactly one wins.

> This is the Oracle port of the MySQL version. The React frontend is identical; only the
> database layer (`server/src/db.js`, the routes, scripts and `database/*.sql`) changed.

## What changed from MySQL

| Topic | MySQL version | Oracle version |
|---|---|---|
| Driver | `mysql2` | `oracledb` (Thin mode, no Instant Client) |
| Auto IDs | `AUTO_INCREMENT` | `GENERATED BY DEFAULT AS IDENTITY` + `RETURNING id INTO :id` |
| ENUM columns | `ENUM(...)` | `VARCHAR2` + `CHECK` constraint |
| Row lock | `SELECT ... FOR UPDATE` | `SELECT ... FOR UPDATE WAIT 10` (waits 10 s, then ORA-30006 and retry) |
| Deadlock error | 1213 | ORA-00060 (retried automatically) |
| Binds | `?` and `IN (?)` with an array | named binds `:name`; `IN` lists built by `inList()` |
| Current UTC time | `UTC_TIMESTAMP()` | `CAST(SYS_EXTRACT_UTC(SYSTIMESTAMP) AS DATE)` |
| Date maths | `DATE_ADD(.., INTERVAL n SECOND)` | `date + n/86400` |
| Boolean in SELECT | `(a > b) AS flag` | `CASE WHEN a > b THEN 1 ELSE 0 END` |
| Column name case | lower case | UPPER CASE from Oracle, lower-cased in `db.js` |
| Empty string | `''` | `''` is NULL in Oracle (does not affect this app) |
| FK indexes | optional | added on every FK column (Oracle best practice for lock behaviour) |

Locking design is unchanged: seat-per-show rows, `FOR UPDATE` in ascending id order, all-or-nothing holds,
lazy expiry using the database clock, retry on deadlock, and `UNIQUE(show_seat_id)` as the last line of defence.
Oracle uses READ COMMITTED by default; row locks from `FOR UPDATE` make the claim safe under that level.

## Setup on Windows

### 1. Install Oracle Database XE
Download **Oracle Database 21c Express Edition** from oracle.com (Database > XE downloads), run the installer, and
set the **SYS/SYSTEM password** when asked. Write it down. Default port is 1521 and the pluggable database is `XEPDB1`.

### 2. Create the app user (once)
Open **Command Prompt** (SQL*Plus is installed with XE) in the project folder:
```
sqlplus system/YOUR_SYSTEM_PASSWORD@localhost:1521/XEPDB1 @database/00_create_user.sql
```
This creates user `seatlock` with password `SeatLock123`.

### 3. Create the tables
```
sqlplus seatlock/SeatLock123@localhost:1521/XEPDB1 @database/schema.sql
```
(You can also paste the script into **SQL Developer** and run it as the `seatlock` user.)

### 4. Start the API
```
cd server
copy .env.example .env
npm install
npm run seed
npm run dev
```
Expected: `Connected to Oracle`, then `SeatLock API listening on :4000`.

### 5. Start the frontend (second terminal)
```
cd client
npm install
npm run dev
```
Open http://localhost:5173 and log in with `demo@example.com` / `demo1234`.

## Prove it works
```
cd server
npm run loadtest -- 100 naive     # several users get the same seat (the bug)
npm run loadtest -- 100 safe      # exactly one winner
npm test                          # 19 integration checks
```

## Troubleshooting

| Error | Meaning / fix |
|---|---|
| `ORA-01017: invalid username/password` | Wrong `DB_USER` / `DB_PASSWORD` in `server/.env` |
| `ORA-12541: no listener` or `NJS-503` | Oracle service not running (open Services, start `OracleServiceXE` and `OracleOraDB21Home1TNSListener`) |
| `ORA-12514: service not known` | Wrong service name; use `localhost:1521/XEPDB1`, not `XE` |
| `ORA-00942: table or view does not exist` | Step 3 was not run as the `seatlock` user |
| `ORA-01950: no privileges on tablespace` | Re-run step 2 (the QUOTA line) |
| `ORA-30006: resource busy` | A row lock waited more than 10 s; the code retries, so a persistent error means a stuck session |

## Known limitations
- Payment is simulated. A real gateway would confirm via webhook before seats become `booked`.
- A user's selection change restarts the 5-minute timer; production should cap total hold time.
- No admin UI: movies and shows come from `seed.js`.
- `/api/demo/*` exists only for the load test; keep `ENABLE_DEMO=false` in production.
